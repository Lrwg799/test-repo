## 二、游戏循环（整体运行原理）

```
┌─────────────── 黑夜 · 吞噬（SampleScene）───────────────┐
│  倒计时 = max(30, 白天碎片数 × 0.5) 秒                    │
│  目标 = 2 + (天数-1) × 1 个                              │
│  蓄力 3 秒 → 吞掉 NPC → 队列 +1                          │
│  蓄力时被 NPC 回头发现 = 失败                             │
└──────────────────────────────────────────────────────────┘
        │ 倒计时结束 && 达标        │ 倒计时结束 && 未达标
        │（黑屏淡出 0.8s）          │（黑屏淡出 → 重开这一夜）
        ▼                          ▲
┌─────────────── 白天 · 跑酷（ParkourScene）──────────────┐
│  太阳倒计时 30 秒                                         │
│  无限横向滚动地形，空格跳跃，捡月亮碎片                    │
│  太阳走完 或 掉下去 → 天数 +1                             │
└──────────────────────────────────────────────────────────┘
```

| 阶段 | 场景 | 结束条件 | 触发脚本 |
|---|---|---|---|
| 黑夜 | `SampleScene` | 月亮倒计时归零 | `MoonCountdown` → `OnCountdownFinish` |
| 夜晚判定 | — | 达标 → 结算；未达标 → 失败重开 | `DevourTarget` / `DevourFail` |
| 白天 | `ParkourScene` | 太阳归零 **或** 玩家掉落 | `MoonCountdown` / `ParkourPlayer.onDeath` → `DayToNight` |
| 过渡 | — | 全程 1.8 秒黑屏 | `ScreenFade` |

## 八、六大核心机制详解

### 1. 跨场景存档（为什么进度不会丢）

| 项 | 说明 |
|---|---|
| 原理 | 场景切换会**卸载所有物体**，普通字段全部清空。改用 `static` 静态类，它属于程序集而不是场景，所以能活过一次场景切换 |
| 代码位置 | `Assets/Common/Scripts/DevourProgress.cs` |
| 生命周期 | 进入 Play 时重置 → 跨场景保留 → 退出 Play 清空 |
| 注意 | 如果关掉 Domain Reload，静态字段会**跨 Play 保留**，需要手动 `ResetAll()` |

### 2. 昼夜循环（三个脚本接力）

```
MoonCountdown.onFinished
   → OnCountdownFinish.OnFinished()
       ├─ DevourTarget.IsTargetMet ? 
       │     ├─ 否 → DevourFail.FailByTargetMissed() → 重开这一夜
       │     └─ 是 → CommitNight() 结算溢出 → ScreenFade.LoadWithFade("ParkourScene")
       └─ 白天
DayToNight.EndDay()（掉落或太阳归零）
   → DevourProgress.NextDay() → ScreenFade.LoadWithFade("SampleScene")
```

### 3. 吞噬操作（蓄力→释放）

| 环节 | 脚本 | 原理 |
|---|---|---|
| 输入 | `ChargeController` | 按住累计 `deltaTime`，达到 `requiredTime` 时置 `full = true` |
| 触发 | `ChargeController` | `full` 状态下松手 → `Fire()` → `onChargeFired.Invoke()` |
| 判定 | `NPCDevourer` | 监听事件 → `Physics2D.OverlapCircle` 找最近 NPC |
| 表现 | `ChargeBarUI` / `ChargeAnimator` | 读 `Progress01` 驱动 UI / 动画 |

### 4. NPC 回头（难度核心）

| 时间点 | 状态 | 玩家该做什么 |
|---|---|---|
| 0.0s | 回头结束 | 立刻开始蓄力 |
| 3.8s | **亮出警告标志** 0.4s | 必须松手 |
| 4.2s | 真的回头 | 已经松手就安全 |
| 4.2~4.7s | 容错期 0.5s | 仍在蓄力也不会死 |
| 4.7~5.7s | 危险期 1.0s | 蓄力 = 失败 |
| 5.7s | 回头结束 | 回到 0.0s |

> 全程固定节奏（`intervalJitter = 0`、`randomizeStartTimer = false`），所以**每一轮都可以提前预判**。

### 5. 无限地形（对象池思想）

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 初始生成 | `BuildInitial()` 生成 9 段 | 覆盖整个屏幕 |
| 每帧平移 | 所有段 `x -= scrollSpeed × dt` | 玩家不动、世界在动 |
| 回收判断 | 段右边缘 < 玩家 x - 14 | 已完全离开屏幕 |
| 回收处理 | `RebuildSegment()` 换一种地形类型 | 复用同一批物体 |
| **关键顺序** | **先全部平移，再统一回收** | 否则算"最右段"会用到旧坐标 → 接缝错位 |

### 6. 屏幕过渡（为什么不闪）

| 难点 | 解法 |
|---|---|
| 切场景时遮挡层会被卸载 | `DontDestroyOnLoad` 让遮挡层常驻 |
| 两个场景各放一个会重复 | 单例检查，多余的直接 `Destroy` |
| 新场景一进来是黑的 | 监听 `SceneManager.sceneLoaded`，自动淡入 |
| `Time.timeScale` 被改过 | 全程用 `Time.unscaledDeltaTime` |

## 十一、学习路径建议

| 顺序 | 学什么 | 对应文件 | 关键收获 |
|---|---|---|---|
| 1 | 输入 → 事件 → 响应 | `ChargeController` → `NPCDevourer` | **事件解耦**：输入不关心吞噬，吞噬不关心输入 |
| 2 | 状态机思路 | `LookBackWatcher` | 用几个计时器字段实现"警告→容错→危险→安全"四态循环 |
| 3 | 跨场景数据 | `DevourProgress` | `static` 类 vs `DontDestroyOnLoad` 两种方案的区别 |
| 4 | 对象池 | `ParkourTerrainBuilder` 的槽位设计 | 为什么运行时**不要** `Destroy` + `Instantiate` |
| 5 | 程序化生成 | `ParkourTerrainBuilder` + `ParkourRunner` | 权重随机 + 规则约束（空隙后必接平地）|
| 6 | 数值设计 | `NightDurationFromCoins` + `DevourTarget` | 用"可跨距离 vs 空隙宽度"这类**不等式**保证关卡永远可通过 |
| 7 | UI 与过场 | `DevourTarget` / `ScreenFade` | 引用（`Text`）+ 事件 + 协程淡入淡出 |

### 最值得记住的三条经验

1. **先算不等式，再做关卡** —— 跳跃滞空 1.05s、空隙需要 0.83s，余量 26% 这个约束定死了所有参数，改任何一个都要重新验算
2. **随机要可控** —— 难度类参数（回头间隔）用固定值，表现类参数（虚晃）才用随机，否则玩家体验会"看脸"
3. **运行时别频繁创建销毁** —— 地形回收改成槽位复用后，卡顿才消失
